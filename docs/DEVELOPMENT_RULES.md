# 개발 규칙

이 문서는 첫 구현을 위한 제안 기준입니다. 제품 범위는 [기획 기준](PRODUCT_PLAN.md), 버전은 [도구와 버전](TOOLCHAIN.md), 작업 흐름은 [CONTRIBUTING](../CONTRIBUTING.md)을 따릅니다. 현재 앱과 아래 디렉터리·실행 명령은 아직 생성하지 않았습니다.

## 구현 원칙

- React + TypeScript + Vite로 브라우저 중심의 앱을 구성합니다. 학습자가 수정하는 예제는 HTML·CSS·JavaScript로 시작합니다.
- 앱 코드에는 TypeScript strict 검사를 적용합니다. 학습용 예제에 TypeScript 지식을 전제로 요구하지 않습니다.
- 화면, 학습 콘텐츠, 진도 저장, 코드 실행을 분리합니다. 외부 서비스나 라이브러리는 필요한 기능이 생길 때 추가합니다.
- 스타일은 CSS Modules와 공통 CSS 변수로 시작합니다. 색상·간격·글자 크기를 공통화합니다.
- 상태는 React 기본 기능으로 관리합니다. 첫 화면 이동은 해시 기반 주소로 구현해 새로고침·뒤로 가기·직접 링크를 지원합니다.
- 코드 입력은 접근 가능한 기본 편집 영역으로 시작합니다. 고급 코드 편집기는 사용자 테스트 후 검토합니다.
- 첫 버전에는 서버·DB·로그인을 추가하지 않습니다. 실제 AI API가 필요해지면 서버 경로와 비용 제한을 별도로 설계합니다.

## 파일 구성 제안

```text
src/
  app/          # 앱 시작, 화면 이동, 공통 배치
  pages/        # 홈, 가이드, 코딩 기초, 실습, 학습 기록
  components/   # 여러 화면에서 사용하는 UI
  content/      # 가이드·개념·미션 데이터
  features/
    learning/   # 학습 흐름과 완료 판정
    playground/ # 코드 입력·실행·결과
    progress/   # 기록 저장·복원·초기화
  lib/          # 공통 함수와 저장 어댑터
  styles/       # 공통 스타일과 CSS 변수
tests/          # 핵심 사용자 흐름 브라우저 테스트
```

필요한 디렉터리부터 만듭니다. 테스트할 로직의 단위 테스트는 해당 파일 가까이에 둡니다. 한 번만 사용하는 동작을 과도하게 공통화하지 않습니다.

## 콘텐츠 작성

- 한국어 입문자를 대상으로 쓰고, 기술 용어는 첫 등장에 쉬운 뜻과 예시를 붙입니다.
- 가이드는 설명·예시·질문·실습 연결을 포함합니다. 코드 작성뿐 아니라 문제 정의·검증·피드백을 함께 다룹니다.
- 콘텐츠는 안정적인 `id`와 `contentVersion`을 가집니다. 제목을 수정해도 학습 기록을 연결할 수 있어야 합니다.
- 미션 데이터에는 목표, 선행 개념, 시작 코드, 힌트, 완료 조건과 연결 가이드 ID를 포함합니다.
- 힌트는 관찰할 지점 → 관련 개념 → 구체적인 수정 방향 순서로 제공합니다.
- 특정 프롬프트나 AI 응답이 항상 정답을 보장한다고 설명하지 않습니다. 사실 설명에는 확인 가능한 출처를 남깁니다.

## 화면과 접근성

- 데스크톱에서는 설명·편집·결과를 나란히, 좁은 화면에서는 순서대로 탐색하도록 구성합니다.
- 키보드로 주요 기능을 사용할 수 있어야 합니다. 입력 요소의 이름, 보이는 포커스, 충분한 대비를 제공합니다.
- 성공·실패를 색만으로 표시하지 않습니다. 오류에는 원인과 다음 행동을 쉬운 말로 적습니다.
- 새로고침과 화면 이동으로 작성 내용이 조용히 사라지지 않게 합니다. 초기화는 영향을 설명하고 사용자가 선택하도록 합니다.
- 모바일은 설명 읽기와 짧은 수정 중심으로 검증합니다. 작은 화면에 데스크톱 편집기를 그대로 축소하지 않습니다.

## 학습 기록과 저장

- 학습 기록은 앱의 `localStorage`에 저장하며 서버로 전송하지 않습니다. 기기·브라우저 간 동기화는 제공하지 않는다고 안내합니다.
- 저장 형식에 `schemaVersion`을 두고, 미션 ID·콘텐츠 버전·진도·작성 내용·확인 결과를 저장합니다. 최초 제안은 `schemaVersion: 1`입니다.
- 읽은 데이터를 검증하고, 손상된 값·저장 차단·용량 부족을 처리합니다. 실패했는데 저장되었다고 표시하지 않습니다.
- 예제 프로그램의 데이터와 학습 앱의 진도 데이터를 분리합니다. 전체 브라우저 저장소를 지우지 않고 앱 전용 키만 초기화합니다.
- 저장 미션은 격리된 실행 화면에서 직접 `localStorage`를 사용할 수 있다고 가정하지 않습니다. 아래 제한된 저장 연결 또는 별도 실행 환경으로 구현·검증합니다.

## 실습 코드 실행

- 학습자 코드를 앱 본문에서 `eval` 또는 `new Function`으로 실행하지 않습니다.
- 실행 결과는 스크립트 실행만 허용하는 격리된 iframe 등으로 분리합니다. 같은 출처 접근 권한을 함께 열지 않습니다.
- 실행마다 결과와 상태를 구분하고, 명시적인 실행 버튼과 실행 화면 초기화 기능을 제공합니다.
- 메시지 통신은 iframe의 `contentWindow`, 실행 ID, 메시지 종류와 데이터 형태를 확인합니다. 진도·인증 정보·임의의 저장 키에 접근하는 통로를 만들지 않습니다.
- 저장 실습이 필요하면 미션별 허용 데이터만 주고받는 저장 어댑터를 사용하고, 실제 브라우저 저장 API와 다른 점을 학습 설명에 명시합니다.
- 외부 네트워크·팝업·상위 화면 이동 등 예제에 필요 없는 동작을 제한합니다. iframe 격리만으로 무한 루프나 자원 소모까지 해결된다고 가정하지 않습니다.
- 첫 실습은 검증된 예제의 제한된 수정부터 지원합니다. 임의 코드 실행 범위를 넓히기 전에 별도 실행 환경과 자원 제한을 검토합니다.

격리 동작의 참고 자료: [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe).

## 검증과 완료 기준

작동을 확인한 만큼만 기록합니다. 아래 명령은 앱 초기화 때 만들 예정이며 지금 실행할 수 있는 상태가 아닙니다.

| 예정 명령 | 목적 |
| --- | --- |
| `npm run dev` | 로컬 개발 화면 |
| `npm run typecheck` | TypeScript 타입 확인 |
| `npm run lint` | 코드 오류·React 사용 규칙 확인 |
| `npm run test` | Vitest로 핵심 로직 테스트 1회 실행 |
| `npm run test:e2e` | Playwright로 주요 사용자 흐름 확인 |
| `npm run build` | 배포용 파일 생성 |
| `npm run preview` | 생성된 배포용 파일 확인 |

- 단위 테스트: 진도 저장·복원, 저장 데이터 검증, 미션 완료 판정 등 실패 영향이 있는 로직에 집중합니다.
- 브라우저 테스트: 가이드에서 실습 이동, 오류 수정, 결과 확인, 새로고침 후 기록 복원 같은 연결된 흐름을 확인합니다.
- 문구·문서만 바뀌면 내용과 링크를 확인합니다. 구현을 그대로 복사한 테스트나 불필요한 테스트는 만들지 않습니다.
- 첫 기능 완료 조건: 연결된 가이드와 미션을 끝까지 사용할 수 있고, 오류·저장 실패를 안내하며, 관련 검사와 화면 확인 결과를 PR에 남깁니다.
- 자동 검사는 앱과 명령이 준비된 뒤 추가합니다. 아직 없는 검사를 통과했다고 기록하지 않습니다.

## 버전과 변경 관리

- 간단한 GitHub Flow를 유지합니다. 작은 작업은 별도 이슈 없이 브랜치와 PR로 처리합니다.
- 직접 의존성은 정확한 버전으로 기록하고 `package-lock.json`을 함께 커밋합니다. 재설치는 `npm ci`를 기준으로 합니다.
- 도구 업데이트는 필요한 이유와 호환성을 확인하고 관련 검사를 통과한 뒤 적용합니다. 설치 오류를 숨기려고 `--force`나 `--legacy-peer-deps`를 기본 사용하지 않습니다.
- 설치 후 실제 버전이 제안과 다르면 [도구와 버전](TOOLCHAIN.md)을 갱신합니다. `package.json`과 잠금 파일이 실제 설치 기준입니다.
