# 개발 규칙

기준일: 2026-11-09. 제품 범위는 [기획 기준](PRODUCT_PLAN.md), 실제 버전과 검증 결과는 [도구와 버전](TOOLCHAIN.md), 작업 흐름은 [CONTRIBUTING](../CONTRIBUTING.md)을 따릅니다.

## 구현 원칙

- React Native + Expo + TypeScript strict로 모바일 앱을 구성합니다. Android를 우선 확인하며 학습 예제는 JavaScript로 작성합니다.
- Expo Router로 세 메뉴와 상세 화면을 연결합니다. 학습 안의 이전 버튼으로 단계 이동, Android 기본 뒤로 가기로 이전 경로 이동을 제공합니다. 경로 이동만으로 진행을 지우지 않습니다.
- StyleSheet와 공통 색상·간격을 사용합니다. 화면, 콘텐츠, 학습 상태, 실습 실행, 저장을 분리합니다.
- Context로 학습 상태를 공유하며 진행 상태 저장소를 useSyncExternalStore로 구독합니다. 순수 reducer는 학습·실습 전이를, 저장소는 복원·순차 저장·실패·초기화를 담당합니다. AsyncStorage로 비민감 진도를 기기에 저장합니다.
- 로그인·서버·DB·실제 AI API는 첫 구현에 추가하지 않습니다. 외부 서비스와 새 도구는 필요와 범위를 확인한 뒤 적용합니다.

## 파일 구성

src/app은 Expo Router 화면·레이아웃·탭, src/components는 공통 UI, src/content는 방법론·문항, src/features/learning은 진행·판정·실행 중 상태·테스트, src/styles는 공통 스타일입니다.

features/playground는 검토된 코드 조각의 실행·비교, features/progress는 저장 형식·검증·저장 순서·상태 표시를 담당합니다. 한 번 사용하는 동작을 과도하게 공통화하지 않습니다.

## 콘텐츠

- 한국어 입문자에게 쉬운 설명과 예시를 제공합니다. 용어는 처음에 뜻을 설명합니다.
- 공식 사실 요약, 자료를 종합한 해설, AICodeT 교육용 예시를 구분합니다. 관련 문장 가까이 출처를 붙이고 발행일과 마지막 확인일을 구분합니다.
- 원문에 없는 표준 단계·효과·점수·사용자 결과를 만들지 않습니다. 특정 프롬프트나 AI 응답이 항상 정답을 보장한다고 설명하지 않습니다.
- 준비된 질문의 답 비교를 실시간 AI 평가처럼 표시하지 않습니다. AI 응답을 제시할 경우 ‘AI 응답 예시’를 표시합니다.
- 콘텐츠는 안정적인 id를 사용합니다. 영구 기록 도입 때 contentVersion과 변경 시 기록 처리 규칙을 함께 추가합니다.
- 설명·예시·질문·피드백·실습 연결을 기본으로 합니다. 이해 확인과 실제 실습 검증을 구분합니다.

## 화면과 접근성

- 작은 화면에서 한 활동씩 진행하고 긴 내용은 스크롤로 접근합니다. 버튼을 고정 높이로 잘라 큰 글자를 숨기지 않습니다.
- 안전 영역, Android 뒤로 가기, 큰 글자, 터치 영역과 접근성 이름을 확인합니다. 기기에서 확인하지 않은 항목은 미확인으로 기록합니다.
- 선택·정답·오답을 색만으로 표시하지 않습니다. 라디오 상태와 문구를 함께 제공합니다.
- 미선택·미확인·오답으로 진행을 넘기지 않습니다. 답을 바꾸면 이전 판정을 무효화합니다.
- 초기화와 다시 풀기는 영향을 설명하고 사용자가 확인하도록 합니다. 복습으로 이전 완료 이력을 조용히 지우지 않습니다.
- 출처 링크가 열리지 않으면 연결·브라우저를 확인하도록 안내합니다.

## 실습 실행

- 준비된 코드 조각 선택에 대응하는 검토된 함수 조합만 실행합니다. 임의 문자열을 eval 또는 new Function으로 실행하지 않습니다.
- 화면 코드와 실제 실행 로직을 맞춥니다. 정답 선택 시 성공 그림만 보여주는 방식으로 대체하지 않습니다.
- 빈 입력·공백 입력·정상 입력을 같은 초기 목록에서 확인합니다. 정상 입력은 한 항목 추가와 기존 목록 보존, 빈 값은 추가 차단과 안내를 요구합니다.
- 코드 조합 변경 시 이전 실행 결과를 무효화합니다. 이해 확인과 실제 실습 검증을 별도 상태로 관리합니다.
- 자유 코드 실행 도입 시 실행 환경과 자원 제한을 별도로 검토합니다. 현재 앱에 iframe 실행 환경이 있다고 가정하지 않습니다.

## 영구 저장

- AsyncStorage 어댑터로 비민감 학습 상태를 기기에 저장합니다. 기기 간 동기화와 서버 전송은 제공하지 않습니다.
- schemaVersion, 콘텐츠 버전, 미션 id, 단계·답·검증 결과를 저장하고 복원 때 형태와 유효성을 검사합니다.
- 손상·용량 부족·저장 실패를 처리합니다. 실패했는데 저장됐다고 표시하지 않습니다. 연속 저장의 순서를 관리해 오래된 상태가 최신 상태를 덮지 않도록 합니다.
- 예제 데이터와 앱 진도를 분리합니다. 초기화는 앱 전용 키만 제거하며 삭제 전에 확인합니다.
- 복원 전에는 학습 입력을 막고 저장 중·실패를 구분합니다. 형식 손상·버전 불일치·읽기 실패 시 원본을 덮어쓰지 않습니다. 초기화 확인 후에만 지울 수 있습니다.
- 현재 schemaVersion과 contentVersion은 각각 1입니다. 콘텐츠 변경 시 내용과 기록 호환성을 검토하고 버전을 함께 갱신합니다. 자동 마이그레이션은 아직 제공하지 않습니다.

## 실제 명령과 검사

| 명령 | 목적 |
| --- | --- |
| npm start | LAN 개발 서버, Expo Go 연결 |
| npm run typecheck | TypeScript 검사 |
| npm run lint | 앱 소스 정적 검사 |
| npm test | Jest로 핵심 학습 로직 검사 |
| npm run check:dependencies | Expo SDK 호환 버전 검사 |
| npm run doctor | 프로젝트 구성·네이티브 의존성 진단 |
| npm run export:android | Android용 JavaScript·자산 번들 생성. APK 빌드가 아님 |

- 테스트는 진행 조건·완료 판정·결과 무효화·저장 복원 등 실패 영향이 있는 동작에 집중합니다.
- 번들 생성, 기기 실행, 사용자 테스트를 구분합니다. 웹 미리보기 검사를 네이티브 화면 검증으로 표시하지 않습니다.
- 비밀키·실제 환경값·서명 파일은 커밋하지 않습니다. 직접 의존성은 정확한 버전, 간접 의존성은 package-lock.json으로 고정하고 재설치에는 npm ci를 사용합니다.
- 버전 변경 시 실제 설치·잠금 파일·TOOLCHAIN을 함께 맞춥니다. 실패를 감추기 위한 --force·--legacy-peer-deps는 사용하지 않습니다.
- 작업 브랜치 → 수정·확인 → PR을 지킵니다. 외부 반영과 병합은 사용자가 승인한 범위에서 진행합니다.
