# Android 확인 기록

기준일: 2026-11-10. 실제 기기 확인과 자동 검사를 구분합니다.

## 확인된 사실

- 2026-11-10 사용자가 ① 앱 완전 종료 후 진도 복원 ② 기록 삭제 취소 시 유지 ③ 기록 삭제 후 재실행해도 초기화 유지에 대해 “세 항목 모두 정상”이라고 보고했습니다. 이는 사용자 보고이며 자동화한 실기기 검사나 입문자 관찰 결과가 아닙니다.

- 2026-11-10 사용자가 “버튼 검증은 끝났어.”라고 보고했습니다. 개별 버튼 목록은 전달되지 않았으며 저장·복원·초기화, 큰 글자·뒤로 가기까지 통과한 것으로 해석하지 않습니다.
- SDK 58 전환 후 사용자가 Android Expo Go에서 “확인해봤어. 잘 작동해.”라고 보고했습니다.
- 이 보고는 코드 실습·영구 저장 기능을 추가하기 전의 앱 실행 확인입니다. 모든 화면, 접근성, 저장 기능을 검사했다는 뜻으로 확대하지 않습니다.
- 코드 실습·저장 추가 후 타입·린트, Jest 33개, Android Hermes 번들 생성을 확인했습니다. 테스트의 저장 장치는 메모리 어댑터이며 실제 Android 저장 공간 검증과 다릅니다.
- 패키지 버전은 SDK 58 전환 당시와 동일합니다. 기존 Expo 호환 검사·Doctor 결과와 보안 경고는 TOOLCHAIN을 참고합니다.

## 이번 구현

- 실습: 공백 제거 여부와 빈 문자열 차단 여부를 선택합니다. 준비된 함수를 실행해 빈 입력·공백·정상 입력의 실제 목록과 안내를 비교합니다. 임의 코드는 실행하지 않습니다.
- 완료: 현재 풀이의 이해 확인과 세 입력의 실행 검증이 모두 통과해야 오류 수정 미션 완료입니다. 코드 변경은 실행 결과를 지우며, 다시 풀기는 답·실습을 지우고 이해 확인 완료 이력만 유지합니다.
- 저장: AsyncStorage의 앱 전용 키 @aicodet/progress에 schemaVersion 1, contentVersion 1, 미션 id, 단계·답·판정·완료 이력·코드 선택·실행 결과를 저장합니다. 계정이나 서버로 보내지 않습니다.
- 복원: 최초 읽기 전에는 학습 입력을 받지 않습니다. 구조·버전·답 범위·단계와 결과를 검증하고 실행 결과는 현재 코드의 예상 실행 결과와 대조합니다. 손상·버전 불일치·읽기 실패는 원본을 유지하며 다시 읽기나 사용자가 확인한 초기화를 제공합니다. 자동 버전 마이그레이션은 없습니다.
- 저장 순서: 변경마다 순서대로 저장하고 최신 요청 결과로 상태를 표시합니다. 실패 시 현재 메모리 상태를 유지하고 다시 저장할 수 있습니다. 저장 중 강제 종료하면 마지막 변경이 남지 않을 수 있습니다.
- 삭제: 확인 대화상자 후 대기 중 쓰기가 끝나면 앱 전용 키만 제거합니다. 삭제 실패는 성공으로 표시하지 않습니다.

## 휴대전화 확인 항목과 상태

1. Expo Go에서 앱을 다시 불러오고 이해 확인 네 문항을 마칩니다. 코드 실습 버튼이 열리는지 확인합니다.
2. 두 선택을 기본값으로 실행합니다. 빈 입력과 공백은 실패하고 정상 입력만 통과해야 합니다.
3. 빈 문자열 차단만 켭니다. 빈 입력은 통과하고 공백 입력은 실패해야 합니다. trim도 켜면 세 입력 모두 통과해야 합니다.
4. 코드를 다시 바꾸면 결과와 현재 미션 완료 표시가 사라지는지 확인합니다.
5. **사용자 확인 완료:** 저장 중 표시가 사라진 뒤 Expo Go를 완전히 종료하고 같은 프로젝트를 다시 엽니다. 단계·답·코드 선택·실행 결과가 복원되는지 확인합니다. 저장 중 종료와 혼동하지 않습니다.
6. 내 기록에서 다시 풀기를 취소하면 기록이 유지되는지, 확인하면 답·실습이 초기화되고 이해 확인 이력은 남는지 확인합니다.
7. **사용자 확인 완료:** 학습 기록 모두 지우기를 취소하면 그대로인지 확인합니다. 삭제를 확인한 뒤 다시 실행해도 기록이 없는지 확인합니다.
8. Android 뒤로 가기, 작은 화면, 큰 글자 설정에서 선택·실행·저장 상태·삭제 확인에 접근할 수 있는지 확인합니다.

위 5·7번 외에 개별 실습 결과·다시 풀기·큰 글자·뒤로 가기는 항목별 결과를 아직 받지 않았습니다. 기록 읽기 오류 화면에 스크롤을 추가한 변경도 별도 기기 확인이 필요합니다. 결과를 실제로 관찰한 뒤에만 미확인 상태를 갱신합니다. 입문자 사용성 평가와 교육 효과 검증은 별도 후속 작업입니다.
