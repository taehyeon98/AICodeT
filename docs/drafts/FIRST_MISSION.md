# 첫 구현 미션 기획서 — 빈 할 일이 추가되는 이유

상태: 사용자 검토용 초안 · 최초 작성 2026-11-08 · 앱 미구현

관련 문서: [전체 기획](../PRODUCT_PLAN.md), [화면 초안](FIRST_MISSION_SCREENS.md)

이번 단계의 산출물은 미션 기획과 화면 초안입니다. 기존 기획·기술 제안을 확정하거나 앱을 구현하는 작업은 포함하지 않습니다. 2026-11-09 요청에 따라 초안의 GitHub 업로드와 검토 PR 작성을 진행하며, 병합은 별도 확인합니다.

## 1. 미션의 위치와 대상

전체 커리큘럼의 네 번째 미션인 ‘오류 고치기’를 첫 구현 대상으로 선택합니다. 첫 구현 순서와 학습 순서는 다릅니다. 앞선 미션을 구현하기 전에도 체험할 수 있도록 필요한 기초 설명을 포함합니다.

- 대상: AI로 작은 프로그램을 만들어봤지만 오류 상황에서 무엇을 확인하고 요청해야 하는지 모르는 입문자.
- 상황: AI가 작성한 예제 할 일 앱에서 입력하지 않고 추가 버튼을 눌러도 빈 항목이 생김.
- 중심 질문: “AI가 고쳐준 결과를 무엇을 기준으로 확인할까?”
- 학습 시간 가설: 10~15분. 실제 사용자 테스트로 조정하며 보장 시간으로 표시하지 않음.
- 이번 학습의 중심: 문제 관찰 → 기대 동작 작성 → 작은 수정 요청 → 결과 검증.

## 2. 학습 목표와 관찰할 증거

| 목표 | 사용자가 하는 행동 | 확인 방법 |
| --- | --- | --- |
| 문제를 재현한다 | 아무것도 입력하지 않고 추가하여 빈 항목 확인 | 재현 활동 + 실제 동작 선택 |
| 요구사항을 구체화한다 | 현재 동작, 기대 동작, 유지할 기능 작성 | 작성 내용과 점검표 비교. 문장 자동 채점 없음 |
| 필요한 기초를 이해한다 | 조건문으로 빈 입력을 거르는 이유 설명 | 공백 입력 결과 예상 문제 + 코드 설명 |
| 수정 결과를 검증한다 | 정상 입력·빈 입력·공백 입력을 각각 확인 | 예상과 실제 결과 비교 |
| 배운 원칙을 돌아본다 | AI에게 다시 요청할 때 필요한 정보 정리 | 짧은 회고 저장. 이해도 점수로 환산하지 않음 |

학습 목표를 수행했는지와 장기적으로 실력이 향상되었는지는 구분합니다. 미션 완료를 실력 인증으로 표현하지 않습니다.

## 3. 단계별 콘텐츠와 활동

### ① AI 개발 개념: 고치기 전에 기준부터

화면 제목: **AI가 고쳤다고 하면, 끝일까요?**

설명 초안:

> AI에게 수정을 부탁하기 전에, 무엇이 잘못됐고 어떻게 동작해야 하는지 정해보세요. 같은 방법으로 문제를 다시 일으킬 수 있으면 설명하기 쉬워집니다. 수정한 뒤에는 정상적인 입력과 예외적인 입력을 함께 확인합니다.

- 모호한 요청: “이 앱이 이상해. 고쳐줘.”
- 개선한 요청: “입력하지 않고 추가를 누르면 빈 항목이 생겨. 빈 입력은 안내만 하고, 글자를 입력했을 때는 지금처럼 추가되게 해줘.”
- 작은 질문: “수정 전에 먼저 확인할 것은?” → 문제를 일으킨 동작과 기대하는 결과.
- 버튼: `문제 직접 확인하기`.
- 첫 화면에는 코드 편집기를 열지 않습니다.

### ② 문제 발견: 직접 재현하기

- 예제 앱에는 `기획 정리하기` 한 항목을 미리 넣습니다.
- 사용자가 입력칸을 비운 채 `추가`를 누르면 빈 항목이 생깁니다. 학습 안내에서 “빈 항목이 한 개 추가됐어요”라고 알려 시각적으로도 확인할 수 있게 합니다.
- 사용자가 정상적인 내용을 입력하면 정상적으로 항목이 추가됩니다.
- 질문: “기대한 동작과 달랐던 점은 무엇인가요?”
- 선택 예시: `빈 항목이 추가됐다` / `추가 버튼을 누를 수 없었다` / `기존 항목이 모두 사라졌다`.
- 재현하지 못했을 때는 정답 대신 “입력칸을 비우고 추가를 눌러보세요”라는 힌트를 제공합니다.

### ③ 요구사항: AI에게 요청할 내용 정리하기

빈 입력뿐 아니라 스페이스만 넣은 경우도 의미 있는 할 일이 아니라는 조건을 안내합니다.

입력 필드는 세 개로 나눕니다.

1. **현재 동작:** 어떤 행동을 했더니 어떤 결과가 나왔나요?
2. **원하는 동작:** 빈 입력과 공백만 있는 입력은 어떻게 처리해야 하나요?
3. **유지할 동작:** 정상적인 할 일 추가와 기존 목록은 어떻게 되어야 하나요?

세 필드를 합친 요청문을 미리 보여줍니다. 필드의 작성 여부만 확인하고, 표현의 품질을 임의로 자동 채점하지 않습니다. 사용자가 점검표와 예시를 보고 직접 보완합니다.

점검표: 재현 방법 / 빈 입력 처리 / 공백 입력 처리 / 정상 동작 유지.

예시 보기에는 **AI에게 보낼 요청문 예시**라고 표시합니다. 입력한 글을 AI가 실시간으로 분석했다고 설명하지 않습니다.

### ④ 코딩 기초: 조건을 확인하고 멈추기

- `text`: 사용자가 입력한 글자를 담은 값.
- `trim()`: 글자 앞뒤의 공백을 제거한 새 문자열을 얻는 동작.
- `if`: 조건이 맞으면 안쪽 동작을 실행하는 문법.
- `return`: 현재 함수를 여기서 끝내는 동작.

설명은 한 번에 짧게 보여주고 예제 코드에서 연결된 줄을 강조합니다. 전체 HTML·화면 갱신 코드는 접어두고 입력 검사 부분에 집중합니다.

이해 확인: “스페이스만 입력했을 때, 공백을 제거한 뒤에는 어떤 값이 남을까요?”

오답에는 관련 예시를 다시 보여줍니다. 정답을 맞혔다는 이유만으로 전체 미션을 완료 처리하지 않습니다.

### ⑤ 수정·검증: 작게 바꾸고 확인하기

기본안은 입력 검사 부분만 수정하는 제한된 코드 편집입니다. 전체 프로그램을 처음부터 작성하게 하지 않습니다.

- 시작 예제는 입력을 바로 추가하므로 빈 입력과 공백 입력을 허용합니다.
- 힌트는 `확인할 위치` → `필요한 개념` → `수정 예시` 순서로 열립니다.
- 마지막 힌트는 **AI 응답 예시 · 미리 준비된 설명**으로 표시합니다.
- 코드 변경 후 이전 실행 결과는 `다시 확인 필요` 상태로 바뀝니다.
- 자동 동작 검사는 현재 코드가 아래 사례에서 어떻게 동작하는지 확인합니다. 특정 코드 문자열이 들어갔는지만 검사하지 않습니다.

각 사례는 동일한 초기 목록에서 독립적으로 검사합니다.

| 입력 | 기대 동작 | 확인할 것 |
| --- | --- | --- |
| `우유 사기` | 한 항목 추가 | 기존 항목 보존, 빈 입력 안내 없음 |
| 빈 문자열 | 추가하지 않음 | `할 일을 입력해주세요` 안내 |
| 스페이스 3개 | 추가하지 않음 | 같은 안내, 빈 항목 없음 |
| `  우유 사기  ` | 앞뒤 공백을 제거해 한 항목 추가 | `우유 사기`로 표시 |

검사 중 문법 오류가 나면 위치와 다음 확인 행동을 안내합니다. 자동 검사 결과는 코드 동작 확인이며, 요청문이나 이해도를 AI가 채점한 결과가 아닙니다.

### ⑥ 돌아보기: 다음에도 쓸 수 있는 방법

- “문제를 재현할 때 어떤 동작을 했나요?”
- “수정 후 정상 입력도 확인해야 하는 이유는 무엇인가요?”
- “다음에 AI에게 오류 수정을 요청한다면 어떤 정보를 전달하겠어요?”

최소 한 문장의 회고를 작성하게 하되 의미를 자동 채점하지 않습니다. 다음 단계로 `조건문 다시 보기`와 `다른 입력 오류 살펴보기`를 제안할 수 있습니다. 미구현 후속 콘텐츠는 연결 가능한 것처럼 표시하지 않습니다.

## 4. 미션 완료 조건

다음 활동을 마치면 **이 미션의 활동 완료**로 표시하는 안입니다.

- 빈 항목 문제를 재현하고 실제 동작을 확인했다.
- 요청문 세 필드를 작성하고 조건 점검표를 확인했다.
- 공백 처리 예상 문제에 답하고 피드백을 확인했다.
- 현재 코드가 네 가지 입력 사례를 통과했다.
- 회고를 작성했다.

실패한 항목은 다시 시도할 수 있고, 재시도 횟수로 감점하지 않습니다. 읽기·재현·코드 검사·회고 상태를 구분합니다. 개발 중 테스트에서는 완료 조건이 실제로 적용되는지 별도로 확인합니다.

## 5. 구현 시 완료 기준과 범위

사용자가 승인한 뒤 구현할 기준입니다.

- 개념 설명부터 회고까지 하나의 흐름으로 사용할 수 있다.
- 빈 입력·공백 입력·정상 입력을 구별하고, 변경한 코드의 최신 결과를 보여준다.
- AI 응답 예시와 실제 사용자 작성 내용을 명확히 구분한다.
- 키보드로 주요 입력과 버튼을 사용할 수 있고 모바일에서 설명·실습 순서가 유지된다.
- 저장 성공·실패와 작성 내용 초기화의 영향을 안내한다.
- 기록은 기기 안에 저장하며, 초기 코드와 수정 코드의 상태를 구분한다.

이번 미션에는 실시간 AI 연결, 회원가입, 데이터베이스, 점수·순위, 코드 자동 수정 기능을 넣지 않습니다. 실행 환경과 설치 버전은 구현 승인 단계에서 확인합니다.

## 6. 검토받을 선택과 다음 단계

이번 초안에서 제안하는 기본안:

1. 코드보다 AI 개발 원칙을 먼저 설명한다.
2. 빈 입력과 공백 입력을 함께 다룬다.
3. 요청문을 세 필드로 나눠 작성하게 한다.
4. 코드는 입력 검사 부분만 직접 수정한다.
5. 완료는 활동과 동작 검사로 판단하고 별도의 실력 점수는 만들지 않는다.

사용자 검토 후 기획·화면을 수정합니다. 이후 앱 구현, 패키지 설치, 커밋·업로드·PR·병합은 수행할 범위를 먼저 설명하고 승인을 받습니다. 기존 문서의 자기 검토 후 병합 규칙보다 사용자의 사전 확인 요청을 우선합니다.
