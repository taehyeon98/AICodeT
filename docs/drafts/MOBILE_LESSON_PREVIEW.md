# 모바일 학습·완료 화면 초안

작성일: 2026-11-09 (한국시간)

상태: 모바일 학습 화면 설계 초안. 2026-11-09 사용자 승인에 따라 PR #5에 포함합니다. 이 미리보기는 실제 앱·AI 연결·학습 데이터 저장을 구현한 상태가 아닙니다.

## 학습의 범위

첫 미션인 ‘빈 할 일이 추가되는 이유’를 모바일에서 짧게 체험할 수 있게 구성합니다. 이번 초안은 개념을 읽고 문제를 고르는 단계이며, 직접 코드를 수정하고 검사하는 전체 미션을 대체하지 않습니다.

목표는 문제를 재현하는 방법, 좋은 수정 요청의 조건, 공백 처리 기초와 검증 대상을 이해하는 것입니다. 목표 시간은 3~5분의 설계 가설이며 아직 사용자에게 측정하지 않았습니다.

## 화면 흐름

| 화면 | 내용 | 상호작용 |
| --- | --- | --- |
| 1. 개념 | 수정 전에 실제 동작과 기대 결과를 정하기 | 짧은 설명 읽고 시작 |
| 2. 문제 관찰 | 빈 입력으로 추가했을 때 생긴 빈 항목 예시 | 관찰한 문제 선택 |
| 3. 요청 작성 | 재현 방법·기대 결과·유지할 동작이 포함된 요청 | 세 요청 중 구체적인 요청 선택 |
| 4. 코딩 기초 | 앞뒤 공백을 제거한 결과로 빈 입력 판단 | 코드 빈칸에 들어갈 `trim` 선택 |
| 5. 검증 계획 | 정상·빈·공백 입력을 함께 확인 | 적절한 검증 대상 선택 |
| 6. 완료 | 이번에 다룬 내용 세 가지와 한계 | 다시 체험하기로 초기화·처음 화면 이동 |

화면 상단에는 이전 버튼과 진행 표시, 중앙에는 한 가지 설명이나 문제, 아래에는 큰 확인 버튼을 둡니다. 문제에 집중하는 동안 홈의 하단 메뉴는 표시하지 않습니다. 작은 화면에서 입력 키보드가 없어도 핵심 활동을 끝낼 수 있도록 구성합니다.

## 문제와 피드백 원고

### 관찰

- 상황: 입력칸을 비워두고 추가를 눌렀더니 기존 ‘기획 정리하기’ 아래 빈 항목이 생김.
- 정답: 입력하지 않았는데 빈 항목이 추가됐다.
- 오답 피드백: 기존 항목은 남아 있고 추가 동작도 실행됐다. 새로 생긴 빈 줄을 다시 살펴보도록 안내.

### 요청

- 정답 예시: ‘빈 입력이나 공백만 넣으면 추가하지 말고 안내해줘. 정상 입력은 추가되고 기존 목록은 유지되게 해줘.’
- 부족한 요청 예시: ‘이상하니까 알아서 고쳐줘’, ‘빈 항목이 안 생기도록 추가 버튼을 없애줘’.
- 피드백: 수정할 조건과 유지할 동작을 함께 전달했는지 설명. 선택 결과는 준비된 답과 비교하며 AI의 실시간 분석으로 표현하지 않음.

### 코딩 기초

`trim()`은 문자열 양 끝의 공백을 제거한 새 문자열을 반환하며 원래 문자열을 바꾸지 않습니다. 따라서 스페이스만 있는 문자열에 적용하면 빈 문자열이 됩니다. [MDN String.prototype.trim(), 확인 2026-11-09](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/trim)

문제는 `const text = input.value.____();`의 빈칸을 고르는 방식입니다. 선택지는 `trim`, `toUpperCase`, `repeat`이며 정답은 `trim`입니다. 이 문맥에서 나머지 선택지가 원하는 공백 제거 동작을 하지 않는다고 설명합니다.

후속 설명에서 빈 문자열일 때 안내 후 `return`으로 현재 함수를 끝내는 코드를 보여줄 수 있습니다. `return`의 기능은 함수 실행 종료이며 앱 전체를 종료한다는 뜻이 아닙니다. [MDN return, 확인 2026-11-09](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/return)

### 검증

- 정답: 정상 입력, 빈 입력, 공백만 있는 입력을 모두 확인한다.
- 오답: 코드의 길이만 확인한다 / 정상 입력만 확인한다.
- 피드백: 문제 상황이 해결됐는지와 잘 되던 기능이 유지되는지를 함께 확인하도록 설명.
- 이 문제의 정답은 ‘무엇을 검사할지’를 고른 결과이며, 실제 코드 테스트가 통과했다는 의미가 아님.

## 상태와 버튼

- 미선택: 확인하기 비활성. ‘답을 선택해주세요’ 안내.
- 선택: 선택한 항목을 테두리와 라디오 상태로 표시하고 확인하기 활성.
- 오답: 이유를 설명하고 다시 선택할 수 있게 한다. 하트 차감·진입 차단 없음.
- 정답: 이유와 다음 화면으로 가는 계속하기 버튼을 보여준다.
- 답 변경: 이전 판정을 지우고 새로 확인하도록 한다.
- 이전 화면: 기존 답을 유지하되 현재 상태를 다시 표시한다.
- 완료: 모든 문제에서 준비된 정답을 확인한 뒤 도달한다. 실제 코드 실행 완료나 실력 인증으로 표시하지 않는다.
- 다시 보기: 이번 체험의 답과 진행을 초기화한다. 저장된 실제 학습 데이터는 다루지 않는다.

## 화면 초안 검증 범위

미리보기에서는 선택과 피드백, 뒤로 이동, 완료와 다시 보기를 확인합니다. 정답·오답 판정은 고정된 문항 데이터와 비교하는 로컬 동작입니다. 코드 실행, 서버 평가, 실제 학습 기록 저장은 없습니다. 화면 미리보기 상태와 실제 제품 진도는 구분합니다.
