# 모바일 첫 버전 범위와 기술 구성 결정안

작성·자료 확인일: 2026-11-09 (한국시간)

상태: 사용자가 모바일 구성 제안에 이어 ‘안드로이드야. 다음 단계 진행해’라고 답했습니다. 첫 버전 범위와 React Native + Expo 방향으로 다음 설치안을 준비하며, 실제 검증 기기는 Android로 확인됐습니다. 설치, 앱 초기화, 커밋, 업로드, PR 병합은 아직 수행하지 않았습니다. 구체적인 적용 범위는 [Android 설치·초기화 계획](ANDROID_SETUP_PLAN.md)에서 확인합니다.

## 1. 추천 결론

**React Native + Expo + TypeScript로 모바일 앱을 만들고, 사용자가 보유한 Android에서 첫 완성 흐름을 검증합니다.** 기기 모델·Android 버전·Expo Go 설치 여부는 아직 확인하지 않았습니다. iOS도 같은 프로젝트의 후속 목표로 두되, 실제 검증 기기 확보 전에는 지원 검증 완료로 표시하지 않습니다.

첫 버전은 ‘방법론 설명 → 이해 확인 → 제한된 코드 실습 → 결과 검증 → 기록’ 한 흐름을 완성합니다. 직접 코드를 다루는 활동을 첫 버전에 포함하되, 긴 자유 입력 대신 준비된 코드 조각을 고르는 방식부터 제공합니다. 이는 기존 자유로운 코드 수정 구상을 줄인 범위입니다.

## 2. 화면과 기능의 경계

하단 메뉴는 **학습 / 방법론 / 내 기록** 세 개를 제안합니다. 기존 초안의 별도 복습 탭은 내 기록 안의 ‘다시 풀기’로 통합합니다. 학습 중에는 하단 메뉴 대신 이전·진행·확인 버튼을 제공합니다.

| 화면 | 첫 버전에 포함 | 완료 조건 |
| --- | --- | --- |
| 홈 | AI 코딩 개발 방법론 버튼, 첫 단원 경로, 학습 이어하기 | 진도와 무관하게 방법론 열람 가능, 실제 저장된 단계로 이어하기 |
| 방법론 목록·상세 | 하네스 상세 원고, 컨텍스트·프롬프트의 출처 있는 짧은 설명 | 정의·사례·교육용 예시·한계·출처를 구분, 빈 상세 페이지로 보내지 않음 |
| 학습 | 개념 → 관찰 → 요청 선택 → 코딩 기초 → 검증 계획 | 미선택·오답·정답·답 변경·이전 이동이 일관되게 동작 |
| 제한된 실습 | 빈 할 일 오류를 재현하고 공백 처리·빈 값 차단 코드 조각을 선택 | 선택에 따른 동작 차이를 확인하고 세 입력 사례를 검사 |
| 완료 | 이해 확인 결과와 실습 검증 결과를 각각 표시 | 선택형 문제만 끝낸 것을 전체 미션 해결로 표시하지 않음 |
| 내 기록 | 진행·완료 상태, 다시 풀기, 학습 기록 초기화 | 앱 재실행 후 복원, 초기화 전 영향 안내·확인, 저장 실패 안내 |

앱에 포함한 학습 콘텐츠와 문제는 오프라인 사용을 목표로 합니다. 외부 원문 열람에는 인터넷이 필요합니다. 출처는 제목·발행일·확인일을 구분하며, 원문을 읽고 해당 설명을 뒷받침하는지 다시 검토합니다. 사례의 성과를 모든 사용자에게 적용되는 효과로 확대하지 않습니다.

로그인, 서버, 실제 AI API, 기기 간 동기화, 결제, 순위, 연속 출석 보상, 자유 코드 편집기와 앱스토어 출시는 후속 범위로 둡니다. 학습 시간 3~5분은 기존 설계 가설이며 측정된 결과가 아닙니다.

## 3. 첫 실습의 구체적인 동작

교육용 할 일 목록에 ‘기획 정리하기’를 넣고 시작합니다. 학습자는 입력한 내용과 추가 후 목록을 비교합니다.

1. 초기 상태에서 빈 문자열과 스페이스만 있는 문자열도 항목으로 추가되는 오류를 재현합니다.
2. 입력값 처리에서 `그대로 사용` 또는 `trim 적용`을 선택합니다.
3. 추가 조건에서 `항상 추가` 또는 `빈 문자열이면 안내 후 중단`을 선택합니다.
4. 선택한 조합에 대응하는 코드와 실행 결과를 보여줍니다. 미리 준비된 함수 조합을 실행하며 임의의 코드 문자열을 평가하지 않습니다.
5. 정상 입력 `책 읽기`, 빈 입력 `""`, 공백 입력 `"   "`을 각각 실행하고 예상과 실제 결과를 비교합니다. 각 검사는 같은 초기 목록에서 시작합니다.

정상 입력은 정확히 한 항목을 추가하고 기존 목록을 보존해야 합니다. 빈 입력과 공백 입력은 목록을 바꾸지 않고 안내해야 합니다. `trim`만 선택하거나 차단 조건만 선택하면 아직 실패하는 사례가 있어야 합니다.

문자열을 새로 입력해 프로그램 전체를 실행하는 자유 코딩 환경으로 표현하지 않습니다. 화면에는 ‘준비된 코드 조각을 선택하는 실습’이라고 안내합니다. 실제 결과는 선택한 로직에서 계산하며, 정답 선택 시 성공 화면만 보여주는 방식으로 대체하지 않습니다. 표시한 코드와 실행 로직이 일치하는지 검사합니다.

이해 확인을 마쳤는지, 실습 검증을 마쳤는지 별도로 저장합니다. 코드를 바꾸면 이전 실습 검증 결과를 무효화하고 다시 검사하도록 합니다. 복습을 시작하는 행동만으로 기존 완료 기록을 지우지 않으며, 기록 삭제는 별도 초기화 기능으로 처리합니다.

## 4. 구현 방식 비교

아래 적합성 평가는 공식 기능 설명과 현재 프로젝트 범위를 바탕으로 한 판단이며, 성능 측정 결과가 아닙니다.

| 후보 | 이번 프로젝트에서의 장점 | 추가 부담·판단 |
| --- | --- | --- |
| React Native + Expo | React·TypeScript 중심으로 Android·iOS 화면과 이동을 구성 | 기존 HTML 화면은 디자인 참고용으로 사용하고 네이티브 컴포넌트로 다시 작성. 모바일 중심인 현재 목표에 추천 |
| React + Vite + Capacitor | 웹 UI를 기반으로 모바일 컨테이너와 기기 기능을 연결 | 웹 실습 편집기를 제품 중심에 둘 때 재검토할 만함. 기존 웹 계획을 유지할 수 있으나 현재는 실제 앱 코드가 없어 재사용 이점이 크다고 단정할 수 없음 |
| Flutter | 여러 플랫폼에서 UI 코드를 공유할 수 있는 후보 | Dart 기반 구현을 새로 도입해야 하므로 기존 TypeScript 제안과 학습 예제 JavaScript 외에 언어가 추가됨 |

기능 근거: [React Native의 프레임워크 권장](https://reactnative.dev/docs/environment-setup), [Expo 프로젝트 소개](https://docs.expo.dev/get-started/create-a-project/), [Capacitor 개요](https://capacitorjs.com/docs), [Flutter 아키텍처](https://docs.flutter.dev/resources/architectural-overview).

## 5. 추천 구성과 버전 상태

실제 확인한 로컬 환경은 Node.js `24.19.0`, npm `11.17.0`입니다. 앱 패키지와 잠금 파일은 아직 없습니다.

| 항목 | 제안 | 확인 수준 |
| --- | --- | --- |
| 앱 기반 | Expo SDK 57, `expo` 후보 `57.0.32` | 공식 SDK 57 템플릿 메타데이터 확인, 설치·빌드 미검증 |
| UI | React Native `0.86.3`, React `19.2.3` | 템플릿 조합 및 공식 SDK 대응표 확인 |
| 언어 | TypeScript `6.0.3`, strict 적용 | 템플릿의 버전 범위 기준 후보 |
| 화면 이동 | Expo Router `57.0.30` | 템플릿 버전 범위 기준 후보. 학습·방법론·기록 탭과 학습 상세 스택 |
| 스타일 | React Native StyleSheet와 공통 색상·간격 정의 | 구조 제안, CSS Modules를 그대로 이식하지 않음 |
| 상태 | React 기본 상태·Context, 학습 진행 로직 분리 | 추가 상태 관리 패키지 없이 시작하는 설계 제안 |
| 저장 | AsyncStorage 후보 `2.2.0`와 저장 어댑터 | 공식 문서의 추천 버전 확인. SDK 57 실제 조합은 설치 전 추가 검증 필요 |
| 검사 | TypeScript 검사, SDK 호환 검사, Jest + jest-expo 중심 핵심 로직 검사 | 검사 도구의 정확한 버전과 전체 의존성은 설치안에서 추가 확정 |

현재 공식 시작 문서는 SDK 58 전환 기간을 안내하며 실물 기기에서 Expo Go를 사용할 경우 SDK 57을 사용하도록 설명합니다. 따라서 초기 화면·학습 확인용 후보를 SDK 57로 잡았습니다. 최신이라는 이유만으로 SDK 58을 선택한 것은 아닙니다. 설치 시점에 이 안내가 바뀌었다면 변경 이유를 설명하고 결정안을 다시 확인합니다. [공식 시작 안내](https://docs.expo.dev/get-started/create-a-project/)

공식 SDK 57 표는 React Native 0.86, React 19.2.3, 최소 Node 22.13.x를 제시합니다. npm에서 확인한 React Native 0.86.3의 Node 조건에도 현재 Node 24.19.0이 포함됩니다. 이는 버전 메타데이터 확인이며 실제 실행 성공을 뜻하지 않습니다. [SDK 57 대응표](https://docs.expo.dev/versions/v57.0.0/), [React Native 0.86.3 메타데이터](https://registry.npmjs.org/react-native/0.86.3)

SDK 57 기본 템플릿은 조회 시 `expo-template-default 57.0.34`였으며 Expo `~57.0.32`, Router `~57.0.30`, TypeScript `~6.0.3` 범위를 제시했습니다. 위 표는 그 범위의 기준 버전을 후보로 기록한 것입니다. 템플릿 전체 패키지를 도입하기로 확정한 것은 아닙니다. 필요한 보조 패키지·타입·검사 도구까지 포함한 정확한 설치 목록을 작성한 뒤 확인받으며, 승인된 직접 의존성은 정확한 버전으로 고정하고 잠금 파일·TOOLCHAIN을 함께 맞춥니다. [템플릿 메타데이터](https://registry.npmjs.org/expo-template-default/57.0.34)

AsyncStorage는 비동기·비암호화 저장소이므로 비밀키나 인증 정보를 넣지 않습니다. 첫 버전에서는 비민감 학습 상태만 앱 전용 키에 저장합니다. `schemaVersion`, 콘텐츠 버전, 저장 데이터 검증과 실패 처리를 둡니다. [공식 저장소 설명](https://docs.expo.dev/versions/latest/sdk/async-storage/)

검사는 완료 판정·선택 변경 후 결과 무효화·입력별 실제 동작·손상된 기록 복원 등 실패 영향이 있는 동작에 집중합니다. Playwright로 HTML 미리보기를 확인한 결과를 네이티브 앱 검증으로 대체하지 않습니다. [Expo의 Jest 안내](https://docs.expo.dev/develop/unit-testing/)

## 6. 개발 기기와 배포

- 사용자가 Android 휴대전화를 보유했다고 확인했습니다. 실제 기기 점검 시 모델·운영체제 버전을 기록합니다.
- Expo Go는 초기 확인용입니다. 독립적으로 설치하는 앱과 동일하게 취급하지 않으며, 배포 가능한 앱 준비 단계에서는 자체 개발 빌드와 설치용 빌드를 검증합니다. [Expo 개발 환경 설명](https://docs.expo.dev/get-started/set-up-your-environment/)
- iOS 시뮬레이터에는 macOS와 Xcode가 필요합니다. Windows에서 iOS 시뮬레이터 실행을 약속하지 않습니다. [Expo Router 실행 안내](https://docs.expo.dev/router/introduction/)
- Expo의 원격 빌드 서비스는 별도 선택 사항이며 프로젝트를 서비스로 전송합니다. 로컬 설치 승인에 계정 연결·원격 빌드 업로드·유료 서비스·스토어 제출까지 포함시키지 않습니다. [Expo Build 설명](https://docs.expo.dev/build/introduction/)

## 7. 승인 후 문서 전환과 구현 순서

기존 [PRODUCT_PLAN](../PRODUCT_PLAN.md), [DEVELOPMENT_RULES](../DEVELOPMENT_RULES.md), [TOOLCHAIN](../TOOLCHAIN.md)은 웹 중심의 이전 제안입니다. 이 문서는 이를 적용 완료로 바꾸지 않습니다. 승인 후 다음 항목을 함께 정리합니다.

| 기존 제안 | 전환할 내용 |
| --- | --- |
| 반응형 웹앱 첫 구현 | 모바일 앱 우선, 플랫폼별 확인 상태 명시 |
| Vite·React DOM·CSS Modules·해시 이동 | Expo·React Native·StyleSheet·Expo Router |
| localStorage | 저장 어댑터 뒤의 AsyncStorage |
| 자유 입력·iframe 실행 | 첫 버전의 준비된 코드 조각 실습, 자유 실행은 후속 검토 |
| 웹 테스트·빌드 명령 | 네이티브 환경에 맞는 실제 명령과 검증 범위 |

진행 순서:

1. 사용자가 첫 버전 범위·기술 방향·우선 검증 기기를 확인합니다.
2. 정확한 전체 설치 목록과 문서 변경안을 준비하고 설치·적용 범위를 확인받습니다.
3. 승인된 초안의 GitHub 반영·PR 병합을 진행하고 최신 main에서 구현 작업 브랜치를 만듭니다. 새 코드와 패키지는 기존 문서 검토 브랜치에 섞지 않습니다.
4. 기본 앱과 홈 → 방법론 → 학습 → 완료 흐름을 구현합니다.
5. 제한된 실습과 저장·복원·초기화를 연결합니다.
6. 실제 기기에서 한 미션을 끝내고 앱 재실행 후 기록을 복원하는 흐름까지 검증합니다.

확인된 결정: 세 메뉴와 제한된 실습을 포함한 모바일 방향으로 진행하며, 검증 기기는 Android입니다. 다음 확인 대상은 구체적인 설치·앱 초기화 범위입니다.
