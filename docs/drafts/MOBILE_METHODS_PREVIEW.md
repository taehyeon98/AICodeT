# 모바일 홈과 개발 방법론 페이지 초안

작성·출처 확인: 2026-11-09 (한국시간)

상태: 사용자 검토용. 홈 → 방법론 목록 → 하네스 설명의 화면·콘텐츠 초안입니다. 2026-11-09 요청에 따라 기존 초안의 GitHub 업로드와 검토 PR 작성을 진행합니다. 앱 구현, 도구 설치와 PR 병합은 포함하지 않습니다.

## 제품 방향

- 최종 목표는 모바일 앱입니다. 데스크톱 좌우 분할보다 한 화면에서 하나의 활동에 집중합니다.
- 듀오링고 공식 설명의 학습 경로, 작은 단원, 단원 가이드와 복습 구성을 참고합니다. 참고 글은 2022년 홈 개편 설명이며 현재 모든 사용자에게 동일한 화면이 보인다는 근거로 사용하지 않습니다. [디자인 참고 출처](https://blog.duolingo.com/new-duolingo-home-screen-design/)
- 색상·로고·문구는 AICodeT용으로 구성합니다. 학습 효과나 사용자의 학습 성과를 추정해 화면에 넣지 않습니다.
- 기존 [첫 미션 화면](FIRST_MISSION_SCREENS.md)은 이전 데스크톱 안으로 보존합니다. 이번 초안은 모바일 홈과 방법론 열람에 집중하며, 미션의 모바일 상세 화면은 다음 검토 대상입니다.

## 1. 홈

화면 순서:

1. AICodeT와 ‘AI와 만드는 첫걸음’ 안내.
2. **AI 코딩 개발 방법론** 버튼. 설명: ‘하네스·컨텍스트·프롬프트, 출처와 함께 알아보기’.
3. 단원명과 세로 학습 경로. 각 학습의 이름을 항상 표시합니다.
4. 하단 이동: 학습 / 방법론 / 복습 / 내 기록.

방법론은 진도와 관계없이 열 수 있습니다. 전체 카드가 누를 수 있는 영역이며, 색뿐 아니라 제목·설명·화살표로 이동을 안내합니다. 이번 초안에서 학습 경로는 순서 예시이고, 복습·기록·실제 미션은 준비 중으로 표시합니다. 가짜 경험치·연속 학습 기록은 넣지 않습니다.

## 2. 방법론 목록

- 제목: AI 코딩 개발 방법론.
- 안내: ‘공식 자료를 바탕으로 개념과 사례를 정리했어요’.
- 하네스 엔지니어링: 상세 페이지로 연결합니다.
- 컨텍스트 엔지니어링, 프롬프트 엔지니어링: 짧은 요약과 출처를 제공하고 상세 설명은 준비 중으로 구분합니다.
- 나열 순서를 필수 학습 순서나 기술의 우열로 설명하지 않습니다.
- 뒤로 가기와 하단 학습 버튼으로 홈에 돌아갈 수 있습니다.

목록 요약의 출처:

| 항목 | 요약 | 근거 |
| --- | --- | --- |
| 프롬프트 엔지니어링 | 모델에 전달할 지시를 작성하고 구성하는 방법 | [Anthropic, Context engineering vs. prompt engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) |
| 컨텍스트 엔지니어링 | 지시뿐 아니라 자료·도구 정보·대화 이력 등 모델에 전달할 정보를 선별하고 관리하는 방법 | 같은 출처 |
| 하네스 엔지니어링 | 에이전트가 작업할 환경과 실행·검증·기록 구조를 설계하는 접근 | [상세 원고와 근거](HARNESS_ENGINEERING.md) |

## 3. 하네스 설명

상단: 뒤로 가기 / 제목 / 영문 용어 / 마지막 출처 확인일.

본문: 짧은 정의 → 공식 사례 → 교육용 적용 예시 → 적용 한계 → 원문 출처.

출처는 관련 문장 가까이 표시하고, 문서 끝에서도 원문 제목과 발행일로 제공합니다. 공식 문서의 사실 요약과 우리가 만든 예시는 다른 라벨을 사용합니다. 모바일에서 긴 사례·출처 목록은 펼쳐보기로 읽을 수 있게 합니다.

원고: [하네스 엔지니어링](HARNESS_ENGINEERING.md).

## 콘텐츠 검증 규칙

1. 설명을 뒷받침하는 원문 구간을 직접 확인합니다. 제목이나 검색 결과만 보고 내용을 확장하지 않습니다.
2. 근거 있는 요약, 자료를 종합한 해설, 교육용 예시를 구분합니다.
3. 회사의 경험 보고를 보편적인 효과나 독립적으로 검증된 성능으로 표현하지 않습니다.
4. 원문에 없는 고정 단계·성공률·속도 향상·표준 인증을 만들어내지 않습니다.
5. 판단이 어려운 내용은 제외하거나 미확인으로 표시합니다. ‘모든 내용이 절대적으로 검증됨’ 같은 표시는 하지 않습니다.
6. 발행일과 마지막 출처 확인일을 구분합니다. 번역·요약을 직접 인용처럼 표시하지 않습니다.
7. 게시 전에는 출처 링크와 문장 대응을 다시 확인합니다. 새 자료가 기존 설명과 충돌하면 차이를 표시하고 재검토합니다.

## 초안의 동작과 다음 승인 범위

- 이번 화면은 홈 버튼, 목록의 하네스 항목, 뒤로 가기와 출처 링크를 확인할 수 있는 검토용 미리보기입니다.
- 화면 선택은 미리보기 상태이며 실제 학습 진도로 저장하지 않습니다.
- 기존 웹 기술 제안과 브라우저 저장 규칙은 모바일 앱 구현 기술로 확정하지 않습니다. 네이티브·크로스플랫폼 방식, 실행 환경과 저장소는 별도 제안 후 확인받습니다.
- 다음 단계는 모바일 학습·완료 화면의 로컬 초안 작성입니다. 새 초안의 업로드, 방법론 원고 확장, 실제 앱 구현과 설치는 별도 확인 후 진행합니다.
