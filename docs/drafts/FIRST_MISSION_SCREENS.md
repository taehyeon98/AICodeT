# 첫 미션 화면 초안

상태: 검토용 구조 초안 · 2026-11-08 · 최종 디자인·앱 구현 아님

상세 내용과 완료 조건: [미션 기획서](FIRST_MISSION.md)

## 화면의 우선순위

**AI 개발 원칙 → 사용자의 관찰·판단 → 필요한 코딩 기초 → 수정·검증** 순서로 정보를 보여줍니다. 첫 화면에는 긴 코드 대신 설명과 구체적인 예시를 배치합니다.

상단에는 AICodeT, 미션 제목과 현재 단계를 표시합니다. 첫 미션 체험에 필요하지 않은 전체 메뉴는 생략합니다. 왼쪽에는 현재 적용하는 AI 개발 원칙, 오른쪽에는 해당 활동을 배치합니다.

## 데스크톱 배치

```text
AICodeT                           미션 · 빈 할 일이 추가되는 이유
개념 → 문제 발견 → 요청 작성 → 코딩 기초 → 수정·검증 → 돌아보기
----------------------------------------------------------------
현재 적용하는 원칙          | 현재 단계의 제목
                           |
짧은 설명                  | 관찰할 앱 / 작성할 요청문 / 수정할 코드
구체적인 예시              | 단계에 필요한 활동만 표시
                           |
기억할 질문                | 결과와 피드백
                           | [이전]                 [다음 단계]
```

## 단계별 주요 요소

| 단계 | 왼쪽 설명 | 오른쪽 활동 | 다음 행동 |
| --- | --- | --- | --- |
| 개념 | 재현과 완료 기준이 필요한 이유 | 모호한 요청과 구체적인 요청 비교 | 문제 직접 확인하기 |
| 문제 발견 | 재현 방법을 기록하는 원칙 | 오류가 있는 할 일 앱, 관찰 질문 | 기대 동작 정리하기 |
| 요청 작성 | 현재·기대·유지할 동작 | 세 필드, 합쳐진 요청문, 점검표 | 필요한 개념 배우기 |
| 코딩 기초 | 조건문과 입력 검사 | 짧은 코드, 공백 처리 예상 질문 | 직접 수정하기 |
| 수정·검증 | 한 부분씩 바꾸고 확인하기 | 제한된 편집 영역, 실행 결과, 사례별 검사 | 결과 돌아보기 |
| 돌아보기 | 검증 근거를 설명하는 원칙 | 회고, 실제 수행한 활동 기록 | 미션 활동 마치기 |

수정 단계에서도 개념 설명은 접어서 다시 열 수 있게 합니다. 힌트는 사용자가 선택했을 때만 순서대로 보여줍니다.

## 모바일 배치

```text
AICodeT
빈 할 일이 추가되는 이유
현재 단계와 단계 선택
----------------------------
AI 개발 원칙 · 짧은 설명
[예시 더 보기]
----------------------------
현재 활동
요청문 / 예제 앱 / 코드 입력
결과와 피드백
----------------------------
[이전]           [다음 단계]
```

설명과 활동을 세로로 쌓고, 단계 선택은 줄바꿈합니다. 페이지 전체를 가로 스크롤하게 하지 않습니다. 코드 편집은 필요한 짧은 구간만 제공합니다.

## 상태와 문구

- 시작 전: `문제를 먼저 확인해보세요`.
- 재현 후: `빈 항목이 추가됐어요. 기대한 동작과 비교해보세요`.
- 입력 누락: `원하는 동작을 먼저 적어주세요`.
- 검사 전: `아직 동작을 확인하지 않았어요`.
- 수정 후: `코드가 바뀌었어요. 다시 확인해주세요`.
- 검사 실패: 실패한 입력, 기대 동작, 실제 동작을 함께 표시.
- 검사 성공: `네 가지 입력 사례에서 기대한 동작을 확인했어요`.
- 저장 실패: `이 브라우저에 저장하지 못했어요. 지금 작성한 내용은 화면에 남아 있어요`.
- 완료: `미션 활동을 마쳤어요`와 수행 활동. 실력 인증·취업 역량 점수는 표시하지 않음.

## 대화에서 보는 초안의 범위

대화 속 화면에서는 단계 버튼으로 여섯 단계의 배치를 살펴볼 수 있습니다. 입력 내용과 검사 결과는 예시이며, 실제 코드 실행·AI 호출·학습 기록 저장은 제공하지 않습니다. 예시 결과를 실제 학습 기록으로 표시하지 않습니다.

- 요청문 세 필드와 제한된 코드 수정의 난도가 적절한가?
