# AICodeT 시연 대본과 제출 준비

정리일: 2026-11-11. SK AIGEN 지원 자료용으로 문제의식·시도·배움이 드러나도록 편집했습니다. 약 3~4분 분량의 녹화 준비안입니다. 실제 영상이나 화면 캡처는 아직 없으며, 독립 APK 설치 확인과 사용자 관찰은 요청에 따라 보류했습니다.

## 짧은 프로젝트 소개문

AI를 처음 알아볼 때 빠르게 늘어나는 정보 때문에 각각이 어떤 내용인지 파악하기 어려웠습니다. AI 코딩에 필요한 내용만 모아 공부할 수 있다면 좋겠다는 생각에서 AICodeT를 시작했습니다. 설명을 읽는 데서 끝나지 않도록 빈 할 일 오류를 관찰하고, 요청 기준을 정한 뒤, 코드 조각을 선택해 세 입력의 실제 결과를 비교하는 첫 미션을 만들었습니다. 저는 주제와 범위·Android 우선·사실 기반 콘텐츠와 검증 방향을 정했고, 구현과 검사 작업에는 Codex를 활용했습니다. 테스트 33개와 자동 검사, APK 생성·서명 검사를 완료했습니다. 이 과정에서 코드 생성뿐 아니라 원인 파악과 완료 기준을 구체화해야 한다는 점을 배웠습니다. 입문자에게 실제로 도움이 되는지와 독립 APK의 기기 실행은 아직 확인하지 않았습니다.

## 녹화 전 원칙

- 실제 실행 환경을 먼저 표시합니다. Expo Go 시연을 독립 APK의 실행 검증이라고 설명하지 않습니다.
- Android 앱 화면을 녹화합니다. HTML 설계 미리보기는 필요할 때만 ‘설계안’으로 표시합니다.
- 앱에 개인 기록이 있으면 삭제 영향을 확인한 뒤 별도 시험 상태를 준비합니다. 영상에 알림·계정·개인정보가 들어가지 않게 합니다.
- 아래 시간은 편집 계획입니다. 실제 사용 소요 시간이나 학습 성과 측정값이 아닙니다.

녹화에서 저장 복원을 직접 보여주려면 저장 완료를 기다린 뒤 앱을 완전히 닫고 다시 여는 장면을 포함합니다. 녹화하지 않은 동작은 문서의 사용자 확인 보고와 구분해 설명합니다. 실제로 관찰되지 않은 성공 화면을 편집해 넣지 않습니다.

## 첨부할 화면 — 아직 미촬영

1. 학습 홈: 방법론 진입과 첫 미션 경로
2. 하네스 상세: 공식 자료·교육용 예시·출처 구분
3. 문항 피드백: 선택과 판정 상태
4. 실습 실패 결과: 빈 값만 차단했을 때 공백 입력 실패
5. 실습 통과 결과: 세 입력 비교와 미션 완료
6. 내 기록: 저장 상태와 현재 진행

캡션에 촬영일·환경(Expo Go/APK)·앱 버전·표시한 동작을 적습니다. 실제 이미지가 준비된 뒤 본문과 연결하며, 현재는 존재하지 않는 파일 링크를 넣지 않습니다.

## 지원서·인터뷰에서 본인 경험을 확인할 질문

아래는 프로젝트를 설명하기 위한 준비 질문이며 공식 면접 문항이 아닙니다.

1. 처음 AI 정보를 알아볼 때 무엇이 이해하기 어려웠고, 그 경험이 앱의 범위에 어떻게 반영됐나요?
2. 코드 중심 기획에 방법론 설명을 넣으려 한 이유는 무엇인가요?
3. AI가 수행한 일과 직접 결정·확인한 일은 무엇인가요?
4. SDK 불일치 또는 빌드 실패에서 어떤 근거로 원인을 좁혔나요? 직접 설명할 수 있는 범위는 어디까지인가요?
5. 테스트 33개 통과로 알 수 있는 것과 알 수 없는 것은 무엇인가요?
6. 실제 입문자의 필요가 예상과 다르면 어떤 가설부터 다시 확인하겠나요?

공고 첨부 기준은 20MB 이내입니다. 약 27.2 MiB의 APK를 포트폴리오 첨부 파일로 사용하지 않고, 본문·소스·빌드 기록 링크를 연결합니다. 실제 제출 화면의 허용 형식은 마지막에 확인합니다.
