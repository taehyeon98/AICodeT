# 입문자 사용성 확인 준비

작성일: 2026-11-10. 진행 안내와 빈 기록 양식입니다. 참가자 관찰이나 결과는 아직 없습니다.

## 대상과 준비

- 코딩을 처음 배우거나 AI로 코드를 만들어본 입문자 3~5명, 1인당 약 15~20분을 계획합니다.
- 이름·연락처 대신 P01~P05 같은 익명 코드와 본인이 말한 경험 수준만 기록합니다. 영상·음성 기록은 별도로 동의를 받은 경우에만 합니다.
- 개발 서버를 사용하는 Expo Go인지 독립 설치본인지, 앱 버전·커밋, Android 기기와 글자 크기를 기록합니다. 개발 서버 연결 문제는 학습 내용 문제와 구분합니다.
- 개인 학습 기록이 있는 기기의 진도를 진행자 판단으로 지우지 않습니다. 새 시험 기록 사용 여부와 초기화 영향을 설명합니다.

## 진행자가 읽을 안내

“AI로 개발하는 방법과 코딩 기초를 배우는 앱을 확인하려고 해요. 사람을 평가하는 시험은 아니에요. 무엇을 하려는지, 이해되지 않는 점을 편하게 말해주세요. 언제든 멈출 수 있어요.”

정답이나 버튼 위치를 먼저 알려주지 않습니다. 도움이 필요하면 참가자가 요청한 내용과 제공한 도움을 기록합니다.

## 관찰할 과제

1. 홈에서 AI 개발 방법 설명을 찾아 하나를 읽고, 본인 말로 무엇에 쓰는지 설명합니다. 출처와 교육용 예시를 구분할 수 있는지 봅니다.
2. 첫 학습을 시작하고 빈 할 일 오류를 설명합니다. 원하는 동작과 유지할 동작을 말할 수 있는지 봅니다.
3. 코드 실습에서 먼저 오류 결과를 확인하고 수정해 세 입력을 통과시킵니다. 실패 이유를 이해한 것인지 선택을 반복한 것인지 구분해 관찰합니다.
4. 성공한 뒤 “정상 입력도 함께 검사한 이유는 무엇인가요?”라고 묻습니다. 필요한 경우에만 힌트를 주고 기록합니다.
5. 기록 저장 상태를 확인하고 앱을 완전히 닫았다가 다시 열어 이어갑니다. 저장 위치와 삭제 영향을 어떻게 이해하는지 묻습니다.
6. “다른 앱에서 비슷한 빈 입력 문제가 생기면 AI에게 무엇을 알려주고 어떤 입력을 확인하겠어요?”라고 묻습니다. 실제로 새 문제를 해결한 결과와 말로 설명한 답을 구분합니다.

## 개선과 재확인

- 관찰 사실, 참가자의 말, 진행자의 해석을 분리합니다. 예: 버튼을 누르지 못했다는 사실만으로 개념을 이해하지 못했다고 단정하지 않습니다.
- 막힘의 영향과 반복 여부를 기준으로 수정 순서를 정합니다. 수정 전후 화면·커밋·같은 과제의 재확인 결과를 남깁니다.
- 인원수에 맞춘 실제 완료 수와 도움 여부만 보고합니다. 소수 관찰을 교육 효과나 전체 입문자에 대한 통계로 일반화하지 않습니다.
- 사용자 관찰이 끝나면 개선 사항과 알려진 제한을 정리한 뒤 제출용 APK·시연 자료를 마무리합니다.
