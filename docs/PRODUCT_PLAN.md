# AICodeT 기획 기준

정리일: 2026-11-09 (한국시간)

Android 우선 모바일 앱의 제품 방향입니다. 기본 화면·첫 선택형 학습·제한된 코드 실습·기기 내 진도 저장을 구현했습니다. 저장 복원·삭제 동작은 사용자 정상 보고를 받았습니다. 개별 실습 결과·접근성 확인과 입문자 사용자 관찰은 아직입니다. 현재 상태는 [README](../README.md), 실제 버전은 [도구와 버전](TOOLCHAIN.md)을 따릅니다.

## 목적과 대상

AI로 코드를 만들어봤지만 무엇을 요청해야 하는지, 생성된 코드가 어떻게 동작하는지, 오류를 어떻게 해결할지 어려움을 겪는 입문자를 돕습니다.

학습 흐름은 **AI 개발 방법 이해하기 → 코딩 기초 배우기 → 프로젝트에 적용하기**입니다. 여기서 AI 개발은 AI 모델을 학습시키는 것이 아니라, AI를 활용해 소프트웨어를 만드는 것을 뜻합니다.

목표는 사용자가 요구사항을 정리하고, 작업을 나누고, AI에 맥락을 전달하고, 결과를 이해·검증할 수 있게 하는 것입니다. SK 아이젠 지원용 포트폴리오에서는 문제 발견, 설계 이유, 실행 결과와 개선 과정을 보여줍니다. 합격이나 학습 효과를 보장하는 표현은 사용하지 않습니다.

## 첫 버전의 화면

| 화면 | 핵심 내용 |
| --- | --- |
| 홈 | AI 개발의 전체 흐름, 짧은 개념 카드, 학습 이어가기 |
| AI 개발 가이드 | 개발 방법 설명, 나쁜 예·개선 예, 작은 질문, 관련 실습 링크 |
| 코딩 기초 | 쉬운 예시, 변수·조건문·함수 등 개념 찾아보기 |
| 프로젝트 실습 | 미션 설명, 요청문·코드 수정, 실행 결과, 단계별 힌트 |
| 학습 기록 | 완료한 미션, 작성 내용, 검증 결과와 이어서 할 일 |

하단 메뉴는 학습 / 방법론 / 내 기록이며 복습은 내 기록의 다시 풀기로 제공합니다. 홈에는 **AI 코딩 개발 방법론** 버튼을 둡니다. 하네스 상세 설명, 컨텍스트·프롬프트 요약에는 출처·발행일·확인일을 표시하고 사실 요약과 교육용 예시를 구분합니다. 듀오링고의 작은 학습 단위와 경로를 참고하되 AICodeT 고유 화면으로 구성합니다.

## AI 개발 가이드의 일곱 주제

| 주제 | 핵심 메시지 | 적용 활동 |
| --- | --- | --- |
| 문제 정의 | 누구의 어떤 불편을 해결할지 정하기 | 대상 사용자와 문제 한 문장 쓰기 |
| 요구사항 작성 | 동작과 완료 기준을 구체적으로 정하기 | 빈 할 일을 등록할 수 있는지 기준 쓰기 |
| 작은 단위로 개발 | 한 기능씩 만들고 확인하기 | 할 일 추가·완료 표시·저장 순서 정하기 |
| 맥락 전달 | 현재 상태, 목표와 제약 전달하기 | 기존 화면을 유지하는 수정 요청 쓰기 |
| 계획·구현·검증 | 접근 방법을 검토하고 실제 동작 확인하기 | 구현 전 계획과 실행 후 결과 비교 |
| 변경 기록·복구 | 잘 작동하던 상태를 남기고 비교하기 | 변경 전후 차이와 되돌릴 시점 고르기 |
| 사용자 피드백 | 실제 사용에서 개선점 찾기 | 관찰 사실과 개선 가설 구분하기 |

카드는 한 문장 설명 → 구체적 예시 → 작은 질문 → 관련 실습 순서로 작성합니다. 특정 AI 도구의 버튼 위치보다 여러 도구에 적용할 수 있는 원칙을 설명합니다.

## 프로젝트 실습: 할 일 관리 앱

아래 여섯 미션은 확장 계획입니다. 첫 버전은 빈 할 일 오류 하나에 집중하며 선택형 이해 확인과 준비된 코드 조각 실습을 연결합니다. 장문의 자유 코드 입력·실행은 후속 검토 대상입니다.

| 미션 | 수행 내용 | 연결할 기초 |
| --- | --- | --- |
| 1. 만들 것 정하기 | 요구사항과 완료 기준 작성 | 입력·처리·출력 |
| 2. 첫 기능 만들기 | 입력한 할 일을 화면에 추가 | 변수·함수·이벤트 |
| 3. 코드 이해하기 | 데이터와 화면의 관계 예상·설명 | 배열·객체 |
| 4. 오류 고치기 | 빈 할 일이 추가되는 오류 재현·수정 | 조건문·입력 검증 |
| 5. 데이터 저장하기 | 다시 열었을 때 데이터 복원 | 저장·데이터 변환 |
| 6. 혼자 확장하기 | 완료한 항목만 삭제하는 기능 추가 | 앞서 배운 개념 종합 |

실습은 설명 읽기 → 동작 예상하기 → 직접 바꾸기 → 실행하기 → 확인하기를 반복합니다. 관련 개념은 실습 안에서 짧게 다시 볼 수 있게 합니다. 마지막 미션에서는 상세 안내를 줄여 새로운 문제에 적용할 수 있는지 확인합니다.

## 첫 구현 범위와 후속 기능

- 첫 버전 목표: 로그인 없는 Android 우선 모바일 앱, 준비된 콘텐츠·예제·힌트, 코드 조각 선택 실습, 기기 내 학습 기록과 초기화. iOS는 후속 기기 검증 대상으로 둡니다.
- 현재 구현: 세 메뉴, 출처 기반 방법론 설명, 첫 선택형 학습·피드백, trim·빈 문자열 차단 선택 실습과 실제 실행 비교. AsyncStorage로 단계·답·실습 결과를 저장·복원하고 실패·초기화를 처리합니다.
- 다음 검증: 남은 개별 실습 결과·접근성 항목을 Android 기기에서 확인하고 입문자 관찰을 진행합니다. 콘텐츠는 앱에 포함되며 외부 출처에는 인터넷이 필요합니다. Expo Go 개발 실행과 독립 앱의 오프라인 실행은 구분합니다.
- AI 응답은 준비된 예시부터 사용하며 **AI 응답 예시**라고 표시합니다. 실시간 AI가 평가한 것처럼 보이게 하지 않습니다.
- 요청문 작성은 명확한 기준과 예시로 피드백합니다. 근거 없는 AI 점수나 단어 포함 여부만으로 이해도를 판정하지 않습니다.
- 완료는 필요한 동작 확인과 짧은 이해 확인을 함께 사용합니다. 읽음·실행함·해결함을 구분합니다.
- 선택형 질문은 ‘이해 확인 완료’로 표시합니다. 현재 이해 확인과 빈 입력·공백 입력·정상 입력의 실제 실행 검증을 모두 통과해야 ‘오류 수정 미션 완료’로 표시합니다. 코드 조합을 바꾸면 이전 검증 결과를 무효화합니다.
- 실시간 AI 힌트, 계정·기기 간 동기화, 커뮤니티, 결제, 자유로운 대형 프로젝트 실행은 후속 검토 대상입니다.
- 배포 서비스와 AI 제공사·모델은 아직 정하지 않았습니다.

## 구현 순서와 검증

1. 오류 수정 미션 하나와 연결된 AI 개발 설명 카드를 완성합니다.
2. 초보자 3~5명에게 사용해보게 하고 멈춘 지점과 필요했던 도움을 관찰합니다.
3. 설명과 화면을 개선하고, 동일한 구조로 가이드와 다른 미션을 확장합니다.
4. 처음 보는 비슷한 문제에서 요구사항 작성·오류 설명·해결을 스스로 할 수 있는지 확인합니다.

테스트 기록에는 익명 참가자 코드, 경험 수준, 미션, 관찰 사실, 도움의 종류, 개선 내용과 재검증 결과를 남깁니다. 소수 사용자 관찰을 일반적인 교육 효과로 확대 해석하지 않습니다. 실제로 수행하기 전까지 결과는 미확인으로 기록합니다.
