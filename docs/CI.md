# GitHub 자동 검사

작성일: 2026-11-10. 구성 파일은 .github/workflows/ci.yml입니다. PR #7에 반영했고 GitHub Ubuntu 환경의 최초 자동 검사가 통과했습니다.

## 실행 조건과 검사

- main 대상 PR의 생성·변경, main 푸시, 수동 실행에서 동작합니다. 문서만 변경한 PR도 검사합니다.
- Ubuntu 24.04에서 .node-version의 Node 24.19.0과 npm 11.17.0을 사용합니다. 실제 실행 버전을 package.json과 대조합니다.
- npm ci로 잠금 파일대로 설치한 뒤 타입·린트·학습/실습/저장 테스트·Expo 패키지 호환·Android 번들·의존성 보안 검사를 차례로 실행합니다.
- Expo 호환 검사는 공식 CLI의 기본 온라인 검사로 수행합니다. Expo Doctor의 전체 진단은 필요할 때 별도로 수행합니다.
- Android export는 JavaScript·자산 생성 검사이며 APK/AAB 빌드나 실기기 검증이 아닙니다.
- 보안 검사는 모든 등급을 로그에 표시하고 높음·치명적 등급에서 실패합니다. 낮음·중간 경고가 있어도 이 단계는 통과할 수 있으므로 통과를 취약점 없음으로 해석하지 않습니다. 네트워크·조회 오류도 숨기지 않습니다.

## 권한과 재현성

- 저장소 읽기 권한만 요청하고 checkout 인증 정보를 남기지 않습니다. 배포·서명·PR 댓글·비밀키가 필요하지 않습니다.
- 공식 actions/checkout과 actions/setup-node의 v6 참조를 2026-11-10에 조회한 커밋 SHA로 고정했습니다. 정확한 SHA는 워크플로에 있습니다.
- npm 다운로드 캐시만 재사용하며 node_modules는 매번 잠금 파일로 설치합니다.
- 같은 PR에 새 변경이 올라오면 이전 검사를 취소합니다. 작업 제한 시간은 20분입니다.
- 저장소의 브랜치 보호 설정은 별도입니다. 워크플로 추가만으로 검사 실패 시 병합이 강제로 차단되는 것은 아닙니다.

공식 문서: [checkout](https://github.com/actions/checkout), [setup-node](https://github.com/actions/setup-node).

## 남은 보안 경고

2026-11-10 같은 package-lock.json의 첫 npm audit JSON 조회는 29개(낮음 1, 중간 28), 이후 높은 등급 차단 기준 검사는 30개(낮음 1, 중간 29)를 보고했습니다. 높음·치명적은 두 번 모두 0입니다. 조회 결과가 달라졌지만 패키지를 수정하지 않았으므로 해결 실적으로 집계하지 않습니다. 마지막 검사의 종료 코드는 0입니다.

- glob·minimatch: 패턴 처리·탐색의 자원 소모 관련 경고입니다. 실제 의존성 경로와 외부 입력 노출을 검토한 뒤 호환 수정안을 적용해야 합니다.
- deepmerge: 객체 병합 결과 오염 관련 낮음 경고입니다. 사용 경로와 입력을 검토해야 합니다.
- 설치 트리에서 glob·minimatch는 Expo CLI/fingerprint·ESLint·Jest 경로, deepmerge 4.3.1은 Jest 설정 경로에서 확인했습니다. 개발·검사 도구 경로라는 사실만으로 위험이 없다고 판정하지 않습니다.
- 경고에는 하위 패키지의 문제가 상위 패키지에 전파된 집계가 포함됩니다. 강제 업그레이드·override는 이번 작업에 포함하지 않았습니다.
- 초기 영향 확인과 별개로 배포 위험 검토·수정은 미완료입니다. 상세 로컬 조회 결과는 Git에서 제외되는 .expo/audit-20261110.json에 있습니다.
